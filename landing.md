# 🧠 PRINCIPIO BASE (antes de la estructura)

Una landing no es una página. Es un **argumento progresivo**:

1. Hook → “esto es para mí”
2. Clarity → “entiendo qué hace”
3. Trust → “esto funciona”
4. Desire → “lo quiero”
5. Action → “lo uso ahora”

Si una capa falla → no conviertes.

---

# 🧱 ESTRUCTURA DE LANDING “PERFECTA” (DevTools / SaaS)

---

## 1. 🧲 HERO — _Hook + Action inmediata_

### 🎯 Propósito:

- Capturar atención
- Explicar valor en <5 segundos
- Permitir acción sin scroll

---

### 🧩 Contenido ideal:

- Headline (outcome claro)
- Subheadline (cómo funciona)
- CTA principal (acción real, no signup)
- CTA secundaria (docs/demo)
- 👉 **Command / interactive element (CRÍTICO para devtools)**

---

### 💡 Ejemplo mental:

```id="hero-ideal"
Catch secrets and compliance issues before every merge.

GitGov scans every commit for leaks, policy violations, and risks.

[ Run on your repo ]   [ View Docs ]

> npx @gitgov/cli init   [Copy]
```

---

### 🧠 Por qué GitLab lo hace bien

GitLab usa:

- Tipografía gigante
- Mucho espacio vacío
- CTA enorme

👉 Resultado:
**no compite por atención → dirige la mirada**

---

## 2. ⚡ “HOW IT WORKS” — _Reduce incertidumbre_

### 🎯 Propósito:

Responder:

> “ok… pero ¿qué tengo que hacer?”

---

### 🧩 Estructura:

3–4 pasos máximo:

```id="how"
1. Install CLI
2. Connect your repo
3. Scan runs on every commit
```

---

### 🧠 Insight:

Si no explicas esto → el usuario inventa complejidad → no convierte

---

## 3. 💥 VALUE PROPS — _Por qué esto es mejor_

### 🎯 Propósito:

Diferenciarte de alternativas

---

### 🧩 Formato:

Cards (3–6 máximo):

- Detect secrets automatically
- Enforce policies in CI
- No config required
- Works with any repo

---

### 🧠 Regla:

No features → **outcomes**

❌ “Policy engine”
✅ “Block insecure code before merge”

---

## 4. 🖥️ PRODUCT PREVIEW — _“Show, don’t tell”_

### 🎯 Propósito:

- Visualizar el producto
- Aumentar confianza

---

### 🧩 Formato:

- Screenshot grande (como el tuyo)
- O animación ligera
- O terminal demo

---

### 🧠 Insight:

Esto convierte porque responde:

> “¿se ve real o es humo?”

---

## 5. 🧪 USE CASES — _“Esto es para mí”_

### 🎯 Propósito:

Que diferentes perfiles se identifiquen

---

### 🧩 Ejemplos:

- For security teams
- For dev teams
- For compliance

---

### 🧠 Insight:

Multiplica conversión sin cambiar producto

---

## 6. 🔐 TRUST — _Eliminar riesgo_

### 🎯 Propósito:

Reducir fricción mental

---

### 🧩 Elementos:

- Logos
- Stats (ya tienes)
- Testimonials
- Open source mention
- GitHub stars

---

### 🧠 Muy importante:

Esto no vende → pero **sin esto no vendes**

---

## 7. 🧠 DEEPER EXPLANATION — _Para el 20% técnico_

### 🎯 Propósito:

Explicar arquitectura / ventaja técnica

---

### 🧩 Contenido:

- Cómo funciona GitGov internamente
- Por qué es mejor que scanners tradicionales
- Integración con Git

---

### 🧠 Insight:

Esto no es para todos → pero convierte usuarios avanzados

---

## 8. 🚀 FINAL CTA — _Close_

### 🎯 Propósito:

Capturar al usuario convencido

---

### 🧩 Formato:

- Repetir CTA
- Más fuerte / directo

```id="cta"
Run your first audit in under 30 seconds.

> npx @gitgov/cli init   [Copy]
```

# 🎨 SOBRE EL ESTILO (tipo GitLab)

Lo que te gusta de GitLab no es casualidad:

## 🔑 Claves visuales:

### 1. Tipografía grande = jerarquía clara

- Headline domina todo
- No hay ruido

---

### 2. Espacio vacío = foco

- Mucho padding vertical
- Elementos respiran

👉 Esto aumenta comprensión

---

### 3. Botones grandes = acción obvia

- No dudas qué hacer

---

### 4. Pocas cosas por sección

- 1 idea por bloque

👉 Esto es CRÍTICO:

> muchas startups meten demasiado en el hero

---

# ⚠️ ERRORES COMUNES (probablemente los tuyos ahora)

Te los digo directo:

### ❌ 1. Hero demasiado “correcto”

→ no tiene interacción (CLI)

### ❌ 2. CTA tipo SaaS (“Start Free”)

→ mata conversión en devtools

### ❌ 3. No hay “flow mental”

→ no guías al usuario paso a paso

### ❌ 4. Mucha explicación, poca acción

→ dev quiere probar, no leer

---

# 🔥 ESTRUCTURA FINAL (ultra resumida)

```id="final-structure"
1. HERO
   - headline
   - subheadline
   - CTA
   - CLI snippet ⭐

2. HOW IT WORKS
   - 3 pasos

3. VALUE PROPS
   - 3–6 beneficios

4. PRODUCT PREVIEW
   - dashboard / demo

5. USE CASES
   - segmentación

6. TRUST
   - logos / stats

7. DEEP DIVE (optional)

8. FINAL CTA
   - repetir acción
```
